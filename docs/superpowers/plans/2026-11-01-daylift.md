# Daylift Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build version 1 of Daylift, a free, installable web app that gives gym-goers today's workout, guides them through it, and tracks progress on their phone.

**Architecture:** A client-only React app. Pure logic lives in `src/lib` and is fully unit tested. Screens read and write one saved record through `src/lib/storage.ts`. Navigation is plain React state, with no router.

**Tech Stack:** React, TypeScript, Vite, vite-plugin-pwa, Vitest, Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-01-daylift-design.md`. Read it first. Its tables hold the exact goal, level and warm-up values.

## Global Constraints

- No paid services, accounts or server. Paid features appear only in the Coming soon list.
- No calorie or diet tracking, calorie targets, weight-loss promises or body comparison.
- Only `src/lib/storage.ts` touches localStorage.
- Project root is `/Users/abijeason/Documents/Claude Code/Daylift`. Do not deploy; publishing needs the owner's separate approval.
- Vite `base` is `/daylift/`. Build asset URLs from `import.meta.env.BASE_URL`.
- Every animation respects `prefers-reduced-motion`.
- Tap targets are at least 44px. Layout works at 360px wide with no horizontal scroll.
- Write user-facing text in plain, friendly English.

## Review Focus

1. **Very little equipment:** a user with nothing selected still gets at least 3 exercises. A workout with fewer matches shows what exists and never crashes.
2. **Bad backup file:** invalid JSON, the wrong shape or a newer version is rejected, and saved data stays untouched.
3. **Odd number entry:** empty, zero, negative, comma decimals and huge values are refused or normalised. Bodyweight exercises work without a weight.
4. **Timer while away:** a rest timer that expired while the phone was locked shows as finished and never goes negative.
5. **Old history after changes:** switching kg to lb, changing goal, or an exercise later removed from the data must not break Progress or a resumed workout.

- [ ] **Step 5: Implement `planner.ts`**

Define `SLOTS: Record<WorkoutType, Muscle[]>` in priority order, big muscles first, long enough for 8 exercises. A, B and C variants set `variant` 0, 1 and 2.

```
candidates = all in file order, where needs ⊆ equipment and level allowed
for each slot until count reached:
  options = candidates for that muscle, not already used
  if options is non-empty: take options[variant % options.length]
if fewer than 3 found: fill from remaining candidates of any muscle
```

Spec steps 2 and 3 combine here, because the curated list holds the bodyweight, band and dumbbell versions and the filter includes them when usable. `nextWorkout` uses `rotation(days)[history.length % days]`. `estMinutes` is the warm-up plus exercise time plus cardio, rounded.
